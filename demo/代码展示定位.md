# 代码展示定位

录屏前把下面四处加入编辑器书签。正式录制只展示关键函数附近，不要从文件顶部慢慢滚动。

## 1. 共享协议：`common/packet.h`

- 第 18 行附近：命令类型，包括输入、屏幕分块和心跳。
- 第 54 行附近：鼠标、键盘、帧信息和分块头的数据结构。
- 第 93 行附近：固定 12 字节包头的编码。

一句话：所有平台共用这一个协议头，避免 Windows 与 Linux 各写一套不兼容逻辑。

## 2. Windows 截屏、JPEG 与分块：`windows/server.cpp`

- 第 808 行附近：GDI `BitBlt` 捕获桌面。
- 第 851 行附近：在内存中编码 JPEG，质量参数为 75。
- 第 870 行附近：发送 `SCREEN_BEGIN`。
- 第 892 行附近：按最大负载拆成多个 `SCREEN_CHUNK`。
- 第 917 行附近：发送 `SCREEN_END`。

一句话：一帧只有开始、所有连续分块和结束都匹配时才算完整。

## 3. 最新帧策略与输入状态：`windows/qt_client/connection_window.cpp`

- 第 564 行附近：解码繁忙时只保留一个最新待处理帧。
- 第 650 行附近：发送远程鼠标事件。
- 第 684 行附近：发送远程键盘事件。
- 第 718 行附近：失焦、断线或关闭输入时释放已按下的键和按钮。
- 第 741 行附近：心跳轮询。
- 第 771 行附近：指数退避重连。

一句话：对远程控制而言，显示最新状态比排队显示每一张旧画面更重要。

## 4. 黑边与坐标映射：`windows/qt_client/remote_screen_widget.cpp`

- 第 187 行附近：按原始比例计算画面实际绘制矩形。
- 第 199 行附近：拒绝黑边输入，并把窗口坐标换算为远端坐标。

一句话：先减去黑边偏移，再按远端分辨率缩放，才能避免点击位置漂移。

## 展示原则

- 每处代码停留 8–12 秒即可。
- 鼠标框出关键条件或字段，不逐行念代码。
- 如果录制时行号有轻微变化，以函数名搜索为准。
- 不展示测试中未证实的性能数字；客户端当前帧信息可以现场读取，但不要把一次测量包装成固定指标。
